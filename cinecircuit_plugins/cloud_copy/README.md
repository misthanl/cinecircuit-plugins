# 跨网盘复制

## 支持功能

- 在不同网盘账号之间复制文件或文件夹，保留文件夹层级。
- 支持已有校验信息秒传、读取文件验证秒传和服务器中转上传。
- 提供手动选择复制、手动全量、定时全量及支持来源的生活事件触发。
- 查看手动复制批次的状态、当前文件、处理阶段和已复制数量；查看运行日志中的文件处理结果。
- 自动规则支持暂停、继续，以及在统计页核对并重试未完成文件。
- 复制完成后可选择仅复制、交接整理或同步本批文件。

### 秒传能力对照

| 源网盘 ↓ / 目标网盘 → | 115网盘 | 123网盘 | 光鸭云盘 | 夸克网盘 |
|---|:---:|:---:|:---:|:---:|
| **115网盘** | ✅ | 🟡 | 🔵 | 🔵 |
| **123网盘** | 🔵 | ✅ | ✅ | 🔵 |
| **光鸭云盘** | 🔵 | 🔵 | 🔵 | 🔵 |
| **夸克网盘（Cookie 接入）** | 🔵 | 🟡 | 🟡 | 🔵 |
| **夸克网盘（Open 接入）** | 🔵 | 🔵 | 🔵 | 🔵 |

- ✅ **可直接尝试秒传**：使用已有校验信息，部分目标需要读取少量文件片段。
- 🟡 **有条件支持**：取决于账号接入方式，见下表。
- 🔵 **需下载校验后尝试秒传**：现有校验信息不足，需要先读取完整文件。

| 有条件的组合 | 条件 |
|---|---|
| 115 → 123 | 目标账号使用支持秒传的开放平台接入方式 |
| 夸克 Cookie → 123 | 源账号使用 Cookie 接入，且目标账号的接入方式支持秒传 |
| 夸克 Cookie → 光鸭 | 源账号使用 Cookie 接入 |

**夸克 Open → 115 不支持直接秒传。**

## 使用方法

### 手动选择文件

1. 在主程序添加源、目标网盘账号，确认连接正常。
2. 安装并启用插件，开启侧边菜单，进入“跨网盘复制”。
3. 选择源网盘，进入目录并勾选文件或文件夹。
4. 选择目标网盘，进入接收文件的目录。
5. 如需读取源文件验证秒传或服务器中转上传，先在插件配置中填写临时目录，再设置复制策略、单文件临时空间上限和复制完成后的处理方式，点击复制。
6. 提交时先检查源文件和目标目录；受理后在“复制记录”中查看批次，等待后台调度处理。

手动选择复制使用本次页面选择的源、目标和策略，不要求先填写自动规则的源、目标目录。

### 查看进度与日志

- “复制记录”显示实际复制结果、传输方式、当前文件、处理阶段、已复制数量、待处理文件和待扫描目录。传输方式包括秒传、中转上传和目标已存在；跳过且没有传输的文件显示“未传输”。打开记录窗口或存在活动批次时，每 5 秒刷新一次。
- 当前进度按文件和处理阶段显示，暂不提供单个文件的字节百分比、速度或预计剩余时间。完整读取文件计算校验期间，已复制数量可能保持不变。
- 复制完成、部分复制成功、已跳过、结果待确认和同名冲突分别显示，不再将所有未成功文件统称为“待核对”。跳过原因会显示在记录中；“已跳过”表示该文件没有复制成功。
- 在插件库的“运行与审计 → 运行记录”中查看手动批次开始、逐文件处理结果和失败原因。手动批次由后台调度执行，运行任务的触发方式可能显示为“定时执行”，日志内容会标明“手动复制批次”。
- 后台每 60 秒检查一次队列和自动规则；通常在下一轮空闲调度时开始手动任务，已有任务运行时可能更晚。这个检查周期与“定时全量”的扫描间隔不同。配套主程序支持空闲结果后，没有任务的轮询不再新增常规运行记录。
- 提交失败或等待超时时，先刷新“复制记录”确认是否已受理；同一页面、选择和策略未变时重试沿用同一批次标识。刷新整个页面后不再保留这个标识，不要将反复提交当作刷新进度。

“数据统计”汇总手动复制与当前规则任务的逐文件明细，可按任务来源、结果和传输方式筛选。复制记录和统计明细末尾的三个点菜单提供重试、删除记录；正在执行的任务暂不可操作，已成功的文件无需重试。重试沿用原复制策略，批次重试只处理未成功文件和剩余目录。删除仅隐藏记录，不删除网盘文件，也不清除防止重复复制的内部记录。暂停、继续和重新扫描仍只控制自动规则。

### 设置自动复制

1. 在插件配置中选择源网盘、源目录、目标网盘和目标目录。
2. 从下列触发方式中选择一种，设置策略后保存。

| 触发方式 | 使用方式 |
|---|---|
| 手动全量 | 在统计页点击“重新扫描”，处理配置的源目录 |
| 定时全量 | 设置执行间隔，默认 60 分钟，保存后等待一个间隔开始首次执行 |
| 生活事件 | 根据源网盘的新变更处理文件，可用性以所选账号提供的选项为准 |

生活事件适合持续跟踪新变更；需要复制已有文件时，可先执行手动全量。

### 选择复制策略

| 策略 | 处理方式 |
|---|---|
| 仅使用已有校验信息 | 使用现有材料尝试秒传；材料不足或未命中时跳过 |
| 允许读取源文件验证秒传 | 按需读取片段或完整下载，补齐校验后尝试秒传；未命中时跳过 |
| 允许服务器中转上传 | 优先尝试秒传；满足流式条件时边下载边上传，需要补齐完整校验信息时先缓存文件再上传 |

115 等目标的片段校验需要选择允许读取源文件的策略。表中的 🔵 组合需要允许完整文件读取，并提供足够的临时空间。

## 注意事项

- 传输方式中的“下载后秒传”表示先将完整文件下载到临时目录，再向目标网盘秒传成功；直接使用已有校验信息或只读取验证片段的成功任务仍显示“秒传”。旧记录未保存这一差别，保留原来的显示。

- 秒传支持表示具备尝试条件，实际命中取决于目标网盘是否接受该文件的校验信息。
- 服务器中转会占用网络带宽；流式上传使用有上限的分片缓存。需要完整缓存时，受单文件临时空间上限约束，默认 10 GiB。
- 临时目录填写容器内已存在且可写的绝对路径，建议使用已映射到 NAS 磁盘的专用目录。未设置时，只允许使用已有校验信息，手动和定时任务均不能读取源文件或中转上传。需要完整缓存时，文件保存在此目录下自动创建的临时子目录中，任务退出时清理子目录。
- “读取源文件验证秒传”可能只读取片段，也可能读取整个文件来补充校验信息；秒传不命中就跳过，不上传文件正文。“服务器中转上传”则允许在秒传不命中时继续上传正文，支持流式上传时不必先完整下载到磁盘。
- 流式上传取决于源文件的校验信息、范围读取能力和目标账号的上传接口；选择“允许服务器中转上传”后自动判断。
- 复制保留源文件；目标出现不同内容的同名文件时会使用后缀区分。
- 切换源目录会清除当前勾选，请在提交前核对所选内容和目标位置。
- 自动规则暂停在当前文件处理结束后生效，继续时使用已保存进度，不影响独立的手动批次。
- 遇到“结果待确认”，可在记录末尾菜单中重试；重试会先核对目标，避免盲目重复上传。未命中秒传时，沿用相同策略重试不保证成功，需要中转上传时请重新选择策略提交。
- 选择交接整理时，目标账号需要开启并配置整理；选择同步本批文件时，目标目录需要匹配已启用的同步映射。请先确认相应开关和规则。
