# 演职员资料完善

## 支持功能

- 补充人物中文姓名、简介、角色信息与头像。
- 结合 TMDB、豆瓣资料完善媒体服务器中的人物信息。
- 按全部人物、资料或角色缺失、姓名未中文化、角色未中文化等范围处理。
- 支持定时执行，以及整理完成、同步完成或刮削完成后触发。
- 保存小体积处理进度与结果统计；每次执行重新扫描，不恢复旧批次或完成标记。

## 使用方法

1. 在主程序中配置媒体服务器，确认可读取和更新媒体信息。
2. 安装并启用插件，选择媒体服务器和处理范围。
3. 按需启用简介更新，设置定时周期或触发事件及延迟。
4. 保存后查看执行记录，确认人物资料和角色更新结果。
5. 需要清理无法完善的人物时，仔细确认范围后再开启相应选项。

## 注意事项

- 完善效果取决于媒体身份匹配以及来源提供的中文资料和图片。
- 人物资料可被多个作品共用，角色信息按作品分别处理。
- 网络异常、来源限制或写入失败时，查看记录中的失败原因后重试。
- “移除无法完善的人物”会修改作品的演职员列表，默认关闭，启用前请核对用途。

## 来源缓存预算（1.0.2）

- 完整保留来源返回字段，包括人物匹配使用的 `works`；有效期 24 小时。
- 仅 `cast-maintenance-v2` 命名空间的 `cache:` 前缀参与缓存淘汰，最多 1,000 条、UTF-8 JSON 总量 8 MiB；两项任一达到限制淘汰旧缓存。
- 单响应超过 190,000 字节时本次处理照常使用，不保存到内存缓存或数据库；写缓存或进度失败不使任务失败。
- 内存来源缓存同样限制 1,000 条、8 MiB 序列化预算，固定 64 把分片请求锁，保持 TMDB 2 / 豆瓣 1 来源并发及现有限流退避。
- 初始化登记通用缓存策略；后台即使插件空闲也每事务最多清理 200 条。积压未清完时跳过新缓存写入，不全量解码历史缓存。
- 新宿主提供通用 `state.prune_cache` / `state.set_cache`；旧宿主可继续处理，但不写持久来源缓存。字节预算不等于数据库页或 Python 对象的实际内存。
